Oracle PL/SQL Unwrapper

A 5–8 minute narrative: understand the format boundary, try the free V2 project, and choose a rights-first path for V1 or complex work.

01 / 10 · INTRODUCTION

When wrapped PL/SQL is all that remains

  • Free open-source support for Oracle wrap V2
  • Clear distinction between V2 and V1
  • Practical routes for complex recovery cases
Oracle PL/SQL UnwrapperAwareness → evaluation → routing
Speaker notes. Introduce the project and its scope. The open-source project restores V2; it recognizes V1 but does not unwrap it. Keep that distinction clear from the beginning, so a single “unwrap” label does not imply support for every Oracle version. The goal of this short overview is to help each audience choose a practical next step without overstating what the public project can do.
02 / 10 · THE PROBLEM

Source can disappear while systems remain

  • Closed projects and missing repositories
  • Contractors or maintainers no longer available
  • Legacy maintenance, audit, and migration needs
Business contextExamples, not customer claims
Speaker notes. These are common situations that can leave a database object in service without an accessible source workflow. A migration may be delayed when tools cannot work from wrapped code as if it were ordinary readable source. The practical first step is to identify what format is present. Once format and scope are known, the free project or a separate recovery discussion can be selected more confidently.
03 / 10 · FORMAT BOUNDARY

Two formats; different routes

  • V1: Oracle 7.2–9.2
  • V2: Oracle 10g through 26ai+
  • The public project supports V2 and recognizes—but does not unwrap—V1
Identify before choosingV1 is not attempted here
Speaker notes. The open-source project treats the two formats differently. V1 recognition is not V1 recovery. For that reason, the public code path must stop and route a V1 case rather than attempting an unsupported operation or implying that the result is available from the free tool. V2 support starts with Oracle 10g and extends through 26ai and later compatible formats as stated by the project.
04 / 10 · FREE V2

A free, open-source V2 capability

  • Java 8+ library and command-line interface
  • Maven: com.github.sftwnd:oracle-plsql-unwrapper:1.0.0
  • Linux x64, Windows x64, macOS arm64/x64 releases
  • BSD-3-Clause license
Source · releases · CLIRepository and releases are the current public route
Speaker notes. Direct developers to the repository and release page for usage details. The CLI is the right public route for local scripts with more than one wrapped object. The project is available as a Java library and command-line interface, and native binaries are published for the listed platforms. This static website does not host the unwrap backend or accept source submissions.
05 / 10 · EXPECTATIONS

Readable logic—not a byte-for-byte original

  • Program logic and identifiers may be recovered
  • Comments and original formatting are usually lost
  • V2 does not record the original PL/SQL version
Set accurate expectationsReview recovered code in context
Speaker notes. Make the recovery boundary explicit. Readable source is not necessarily the exact source file that was originally wrapped. The format does not preserve comments, layout, or the PL/SQL version. Program logic and identifiers can be recovered, but the result is not a byte-for-byte reconstruction. Recovered output should be reviewed and validated in the customer's environment before being treated as the maintained source baseline.
06 / 10 · UPGRADE CONTEXT

Oracle 23ai/26ai and PLS-01918

  • By default, code wrapped with wrap 9.2 or older reports PLS-01918
  • This is not a universal claim across all installations
  • Identify the format before selecting a recovery path
Qualified technical contextNot every configuration behaves identically
Speaker notes. The reported issue is important in upgrade planning, but say “by default” and preserve the qualification. Do not claim that every Oracle 23ai or 26ai environment rejects every older wrapped object. When source is missing, version and format matter to the next step. A case involving old wrap 9.2-or-earlier code may need assessment beyond the public V2 tool.
07 / 10 · MIGRATION AND MAINTENANCE

When teams need to read or move the code

  • Migration tools cannot treat wrapped code as readable source
  • Audit and legacy changes need a reviewable baseline
  • Use the CLI for multiple local objects
Operational needsNo public bulk interface is offered
Speaker notes. For one supported V2 object, use the open-source capability. For a local script with multiple wrapped units, the CLI is designed for local workflow. Managed bulk recovery is a separate service conversation. Neither case changes the public tool's format support. Teams should also preserve the recovered text as a new baseline only after review and testing in their own environment.
08 / 10 · COMPLEX CASES

A separate path for V1 and complex work

  • V1 and difficult recovery cases
  • Managed bulk work and re-wrapping
  • PLS-01918 / Oracle 23ai/26ai questions
Professional recovery by discussionAndrey Shindarev
Speaker notes. Andrey's service covers wrapped PL/SQL from versions 7.2 through 26ai+, including difficult V1 cases, bulk work, and re-wrapping to a specified Oracle version. A re-wrap target cannot be older than the original code. Suitability is discussed case by case; do not promise an outcome. The free project remains available for V2; these services do not change its open-source boundary.
09 / 10 · RIGHTS FIRST

Establish rights before recovery work

  • Customer must demonstrate lawful rights to the code
  • Written confirmation and an NDA are required
  • No unauthorized Oracle internal or third-party code
  • Do not send source with the first inquiry
Eligibility is a preconditionNot legal advice
Speaker notes. The rights requirement is not an optional step. Before commercial work begins, the customer needs to demonstrate rights, provide written confirmation, and sign an NDA. A contact form or an email is not a substitute for that review. The initial conversation can stay high-level without attaching code. No Oracle internal packages or unauthorized third-party code should be sent.
