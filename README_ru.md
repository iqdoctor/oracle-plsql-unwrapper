# Oracle PL/SQL Unwrapper

[English version](README.md)

Библиотека для восстановления исходного PL/SQL-кода из Oracle wrapped-формата V2 (Oracle 10g и новее). Публичный API находится в пакете `com.github.sftwnd.unwrap`.

Единица формата V1 (Oracle 7.2, 7.3, 8, 8i и 9i) распознаётся, но её восстановление не реализовано: о ней сообщает `UnwrapException` с контактами автора, у которого можно получить код восстановления V1: ashindarev@gmail.com или [Андрей Шиндарев в LinkedIn](https://www.linkedin.com/in/ashindarev/). В единице V2 версия PL/SQL не записана.

## Требования

- JDK 17 или новее.
- Доступ в интернет при первой загрузке Maven и его плагинов.

Устанавливать Maven отдельно не нужно: проект содержит Maven Wrapper.

## Сборка

Из корня проекта выполните:

```bash
./mvnw --settings settings.xml clean package
```

В Windows:

```bat
mvnw.cmd --settings settings.xml clean package
```

Сборка запускает тесты: они побайтово сравнивают результат с эталонными файлами из `src/test/resources/samples`.

После успешной сборки JAR-библиотека находится здесь:

```text
target/oracle-plsql-unwrapper-0.1.1-SNAPSHOT.jar
```

## Использование

Точка входа — `com.github.sftwnd.unwrap.Unwrapper`. Формат каждой wrapped-единицы определяется по её заголовку; форматы перечислены в `WrapFormat` (`V1` и `V2`), восстанавливается только `V2`.

Для распаковки SQL-скрипта, включая все содержащиеся в нём wrapped-единицы:

```java
import com.github.sftwnd.unwrap.Unwrapper;

String wrappedScript = ...;
String unwrappedScript = new Unwrapper().unwrapScript(wrappedScript);
```

Каждая wrapped-единица вместе с завершающей строкой `/` заменяется восстановленным текстом. Остальной текст скрипта переносится без изменений, включая окончания строк; после единицы V2 может добавиться строка комментария, см. [Формат V2](#формат-v2). Если вход кончается строкой `/` последней единицы без перевода строки, восстановленный скрипт тоже кончается её `/` без перевода строки. Восстановленный текст использует окончание строк wrapped-единицы (CRLF, LF или CR — то, которым заканчивается строка её заголовка), поэтому скрипт сохраняет свои окончания строк; исключение — CRLF, записанный в тексте единицы V2, см. [Формат V2](#формат-v2). Если у строки заголовка окончания нет, используется разделитель строк операционной системы. Переводы строк внутри строковых литералов следуют тому же правилу: WRAP для Windows хранит их как LF, и в единице с CRLF они снова пишутся как CRLF.

Если перевести wrapped-файл на другие окончания строк, например через `core.autocrlf` в git, восстановленный текст получит те же окончания, и больше ничего не изменится: перевод строки внутри литерала WRAP хранит как `:n`, а возврат каретки — одиночным символом, и конвертеры их не трогают. Чтобы снова завернуть восстановленный текст, WRAP нужно подать окончания строк его платформы. WRAP для Linux заменяет CR перед LF пробелом (10.1–11.2) или сохраняет его в тексте (12.1 и новее), поэтому текст, восстановленный из единицы, завёрнутой в Windows, или из файла, переведённого в CRLF, сначала переводится в LF. Такой перевод безопасен: WRAP для Windows и так хранит переводы строк литералов как LF.

Восстановленная единица начинается с заголовка wrapped-единицы. WRAP копирует оператор `CREATE` из исходного текста до конца имени единицы: с `OR REPLACE` или без него, со схемой, регистром, кавычками и переводами строк. WRAP той же версии даёт восстановленному тексту тот же заголовок, см. [Формат V2](#формат-v2).

Для чтения и записи SQL-файлов в исходной однобайтовой кодировке:

```java
import com.github.sftwnd.unwrap.Unwrapper;

import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;

Path input = Path.of("S.SQL");
Path output = Path.of("S.SQ");
String wrappedScript = Files.readString(input, StandardCharsets.ISO_8859_1);
String unwrappedScript = new Unwrapper().unwrapScript(wrappedScript);
Files.writeString(output, unwrappedScript, StandardCharsets.ISO_8859_1);
```

Текст единицы V2 декодируется в кодировке, которую называет единица, поэтому скрипт с единицами V2 записывается в кодировке, которая его покрывает, см. [Формат V2](#формат-v2).

Параметры передаются конструктору, а `new Unwrapper()` берёт `UnwrapOptions.defaults()`. Параметр `keepStrayCr` сохраняет случайный CR текста V2 вместо замены его пробелом, см. [Формат V2](#формат-v2):

```java
import com.github.sftwnd.unwrap.UnwrapOptions;
import com.github.sftwnd.unwrap.Unwrapper;

Unwrapper unwrapper = new Unwrapper(UnwrapOptions.defaults().withKeepStrayCr(true));
```

По умолчанию `keepStrayCr` равен `false`, если системное свойство `com.github.sftwnd.unwrap.keepStrayCr` не равно `true`: с `-Dcom.github.sftwnd.unwrap.keepStrayCr=true` каждый `new Unwrapper()` сохраняет случайные CR, поэтому приложение может включить это без изменения своего кода. `withKeepStrayCr` задаёт параметр независимо от свойства.

Дополнительные операции `Unwrapper`:

- `unwrap` — распаковать первую wrapped-единицу;
- `unwrapUnits` — распаковать все wrapped-единицы и получить формат, тип и имя каждой. У единицы V2 версия PL/SQL, группа совместимости PL/SQL и `staticSqlAsText` — `null`: их записывает только единица V1;
- `supports` — проверить, есть ли в тексте wrapped-единица поддерживаемого формата.

Ошибки в содержимом wrapped-единиц сообщаются исключением `UnwrapException`.

Для побайтового сравнения результата с эталонным файлом:

```bash
cmp S.SQ /path/to/U.SQL
```

Если `cmp` ничего не вывела и завершилась с кодом 0, файлы полностью совпадают.

## Формат V2

Единица V2 (Oracle 10g и новее) хранит исходный текст в том виде, в каком его нормализовал WRAP, поэтому восстанавливается этот текст, а не исходник: слова без кавычек — в верхнем регистре, комментарии внутри единицы удалены, а их переводы строк остались. Строковые литералы, идентификаторы в кавычках и подсказки сохраняют регистр. Восстановленный оператор — заголовок wrapped-единицы, за которым идёт текст после вида и имени единицы. Предложение TIMESTAMP единицы любого вида, со строковым литералом или `OLD`, и предложение OID типа (у WRAP 10.1 — любого вида) WRAP копирует в заголовок и не включает в текст (WRAP 10.1 оставляет на их месте пробелы, а в восстановленном операторе там стоят предложения), а пробелы перед заголовком копирует, если не отбрасывает их после `/` (см. ниже); то и другое сохраняется. Заголовок без `CREATE`, как в тексте из словаря данных, получает `CREATE OR REPLACE`; заголовки с `EDITIONABLE` или `NONEDITIONABLE` сохраняются как записаны.

Единица называет кодировку своего текста — ту, что была в `NLS_LANG` при заворачивании, — и текст декодируется в ней. Единица, завёрнутая без `NLS_LANG`, называет US7ASCII, какими бы ни были её байты. Такой текст, как и текст в кодировке, которой библиотека не знает, читается как UTF-8, если он допустимый UTF-8, и как ISO-8859-1 иначе, что сохраняет каждый байт. Поэтому в восстановленном тексте могут оказаться символы, которых нет в кодировке, в которой читался скрипт: результат записывается в кодировке, которая их покрывает, например в той, в которой заворачивались единицы, или в UTF-8.

WRAP 12.1 и новее оставляют предложение `SHARING` после имени единицы в заголовке и убирают его из текста, а WRAP 23.26.1 так же поступает с `IF NOT EXISTS` между видом и именем; в восстановленном заголовке они написаны как в исходнике. Единицы вида `ASSEMBLY` (WRAP 11.1 и новее) восстанавливаются так же, как единицы других видов. О единице с заголовком, который библиотека не может прочитать, например с предложением более нового выпуска, сообщает исключение `UnwrapException`, поэтому она не остаётся завёрнутой в восстановленном скрипте. `supports` для такого текста возвращает `true`.

WRAP 12.1 и новее для Linux сохраняют CR исходника с CRLF в тексте единицы, в том числе в строковых литералах, а строки wrapped-файла пишут с LF. В файле с LF текст единицы восстанавливается как есть, с его CRLF, поэтому значение литерала не меняется, а эти выпуски снова дают ту же единицу.

WRAP 10.2–11.2 для Linux заменяют пробелом CR сразу перед LF, в том числе в строковых литералах, но читают исходник блоками по 512 байт и делают это только внутри блока: CR в последнем байте блока, на смещении 511, 1023 и так далее от начала файла исходника, остаётся перед LF, с которого начинается следующий блок. Поэтому из исходника с CRLF получается текст, строки которого кончаются пробелом, а на нескольких из них остаётся CRLF — в местах, которые зависят от смещений в файле исходника, включая удалённые WRAP комментарии, а не от программы. Такой CR вне строковых литералов и идентификаторов в кавычках — случайный (stray): по умолчанию в восстановленном тексте на его месте пробел, как и на остальных строках, а CR внутри литерала или идентификатора в кавычках остаётся как часть значения. Таким считается текст, у которого перед переводами строк вне литералов пробельный символ стоит чаще, чем CR; CR, которые сохраняют WRAP 12.1 и новее, стоят перед переводами строк, поэтому их текст остаётся как есть. С `UnwrapOptions.withKeepStrayCr(true)` текст восстанавливается так, как его хранит единица. Ни один из этих текстов как есть не заворачивается обратно в тот же файл: в восстановленном скрипте CR стоят на других смещениях, и WRAP их там заменяет. Текст, восстановленный с `keepStrayCr`, заворачивается в тот же файл, если комментарий перед каждым CR снова сдвигает его в последний байт блока, поэтому такой файл совпадает с точностью до случайных CR. В дистрибутивах Oracle это два файла ORDS, `ords_migrate` и `upg_oauth`, с 3 и 1 случайным CR, завёрнутые WRAP 10.2 или 11.1 из исходника с CRLF.

Данные единицы проверяются по дайджесту SHA-1 и длине, повреждённые или обрезанные данные сообщаются исключением `UnwrapException`. Строки Base64 могут быть разбиты, склеены или иметь другие окончания — такими их оставляют SQL-клиенты и системы контроля версий.

Удалённый комментарий может оставить след, который при следующем проходе WRAP потерялся бы, поэтому восстановленный скрипт его помечает. Текст, который кончается пробельным символом или переводом строки, как бывает перед удалённым комментарием, получает после себя пустой комментарий `/**/`: текст перед таким комментарием все выпуски сохраняют, а сам комментарий удаляют вместе со следующим переводом строки. После единицы V2 перед строкой, которая следует за строкой `/` и начинается с пробелов, пишется строка `--`: после `/` единицы или анонимного блока WRAP 10.2 и новее сохраняют такие пробелы только после строки комментария, а эту строку удаляют все выпуски. Пометки не спутать с исходником: WRAP 10g и новее удаляют из единицы V2 все комментарии, а также каждую строку `--` сразу после строки `/`. Поэтому в скрипте, восстановленном из их вывода, `/**/` в конце текста единицы V2 — перед переводом строки и её строкой `/` — и строка из одного `--` сразу после строки `/` всегда пометки. Чтобы получить текст без пометок, их достаточно удалить; но тогда WRAP уже не даст из него тот же wrapped-файл.

WRAP 10.2.0.5 и 11.1.0.6 дают из восстановленного текста тот же wrapped-файл с одним исключением: комментарий между именем единицы и следующим словом WRAP удаляет без разделителя, а в восстановленном тексте там стоит пробел. Из проверенных исходников оба выпуска дают одинаковые файлы. WRAP для Linux заменяет CR пробелом, в том числе в строковых литералах, поэтому перед повторным wrap восстановленный текст переводится в LF.

WRAP 10.1.0.3 тоже даёт тот же wrapped-файл. Исходник он сохраняет полнее, чем WRAP 10.2.0.5: имя в тексте — в верхнем регистре, а пробелы и пустые строки перед `/` остаются в тексте и тоже получают пустой комментарий. Все эти выпуски пишут `a000000`, но WRAP 10.1 даёт из одного исходника другой текст, поэтому единица заворачивается заново тем выпуском, которым завёрнута.

Строки `REM`, строки комментария `--` и пустые строки между операторами вне единиц WRAP удаляет, поэтому такая строка бывает в wrapped-файле, только если её добавили после завёртывания, как строки `Rem drv:` в некоторых файлах Enterprise Manager или блок строк `Rem` и пустые строки вокруг операторов в файлах `prvtqopi` и `prvtsqlpatch`. Восстановленный скрипт её сохраняет, как и весь текст вне единиц, а повторный wrap даёт файл без неё. Внутри анонимного блока WRAP 10.2 и новее сохраняют пустые строки и строки `REM`.
